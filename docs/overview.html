stock_news · 시스템 설명서

전일 재료 기반 장전 리포트 시스템

매일 아침 장이 열리기 전에, 전날 장 마감 이후 나온 뉴스·공시·정부 정책을 모아 종목별 호재 강도(1~5)를 매기고 리포트로 보내 주는 시스템입니다. 주문은 하지 않습니다. 최종 매매 판단은 사람이 합니다.

실행 장비 미니PC (PN53, cron) 언어 Python 3.12 표준 라이브러리만 채점 Claude Code (화면 없는 실행) 저장소 github.com/devmoonho/stocknews (private)

01하는 일과 하지 않는 일

하는 일

  • 전일 15:30 ~ 당일 07:00 뉴스·공시·정책뉴스 수집
  • 종목 찾기, 고정 채점표로 호재 강도 채점
  • 리포트 작성 → 메일·텔레그램 발송
  • 다음 날부터 실제 주가 반응 기록
  • 매주 가중치 조절과 재료 유형별 영향 분석
  • 내부망 읽기 전용 API로 RAS에 데이터 제공

하지 않는 일

  • 주문·자동매매 (주문 API를 호출하지 않음)
  • 매수 추천 (점수는 재료의 세기일 뿐)
  • 장중 실시간 감시
  • 수집한 데이터 삭제 (백테스트를 위해 모두 보관)

03아침 절차 8단계

순서는 고정입니다. 4단계만 Claude가 하고, 나머지는 모두 파이썬 스크립트가 합니다. 최종 점수도 Claude가 아니라 스크립트가 계산합니다.

  1. 종목 마스터update_master.py --skip-if-fresh
    키움 REST에서 전 종목과 제외 대상(ETF/ETN·거래정지·관리종목·정리매매·상장폐지 추정), 키움 테마를 받습니다. 네이버 테마 265개와 종목별 편입 사유도 받습니다. 하루 한 번, 약 3~4분.
  2. 수집collect.py
    네이버 시황·전망, 정책브리핑, DART 공시를 모아 SQLite에 저장합니다. 0건이거나 형식이 바뀐 것 같으면 경고를 남기고, 경고는 리포트 맨 위에 그대로 옮깁니다.
  3. 매칭match.py
    기사와 공시에서 종목명·테마 키워드를 찾아 후보 종목을 만듭니다. 공시 수치로 규모 점수, 언론사 수로 확산도 점수를 객관적으로 미리 계산하고, Claude가 읽을 압축본(candidates_digest.md)을 씁니다.
  4. 채점Claude
    고정 채점표(config/scoring_rubric.md)대로 종목마다 항목 점수와 한 줄 근거, 재료 유형을 적습니다. 정부 정책뉴스는 하나씩 모두 읽고, 수혜 종목을 고르지 않은 정책도 검토 기록을 남깁니다. 악재는 점수 없이 따로 표시합니다.
  5. 검증·계산score.py
    객관 점수를 그대로 썼는지, 형식이 맞는지 확인하고 오류가 있으면 Claude가 고칠 때까지 반복합니다. 통과하면 가중치로 최종 점수를 계산해 DB에 저장합니다.
  6. 리포트report.py
    reports/YYYY-MM-DD.md 작성. 손으로 고치지 않고, 수정은 채점 파일부터 다시 거칩니다.
  7. 메일send_report.py
    메일용 HTML(표 레이아웃·인라인 스타일)과 텍스트 대체본을 Gmail로 보냅니다.
  8. 텔레그램 요약send_telegram.py
    호재 상위 7종목, 주의 종목, 수혜 정책을 짧게 보냅니다. 알림 전용 봇만 쓰고, 실거래를 제어하는 봇의 토큰은 절대 쓰지 않습니다.

네이버 증권 시황·전망뉴스 포커스 목록과 기사 본문날짜별로 요청. 하루 1회만, 요청 간격 유지
정책브리핑 (korea.kr)정부 정책뉴스 목록·본문목록은 날짜만, 본문 메타에서 발행 시각을 읽음

키움 REST종목 목록·상태, 테마, 일봉, 지수현재 모의투자 키. 조회만 사용
네이버 테마테마 265개, 설명, 종목별 편입 사유테마 신호에서 기사 내용과 편입 사유가 맞는 종목만 고름

05채점 방식

다섯 항목을 1~5점으로 매긴 뒤 가중평균을 냅니다. 해당 없는 항목(정책 재료가 아니면 정책, 기사 없이 공시만 있으면 확산도)은 빼고 나머지 가중치를 100%로 다시 맞춥니다.

재료 규모공시 수치면 객관 점수
30%
신규성처음 나온 재료인가
25%
확산도언론사 수, 객관 점수
20%
최초/독점세계 최초·독점 공급 등
15%
정책 수혜정책 재료일 때만
10%

현재 가중치 버전 1 (config/weights.json, 2026-11-12 초기값). 막대 끝은 상한 40%. 매주 토요일 실제 주가 반응을 보고 조금씩 바뀝니다.

실제 예: 2026-11-13 1위 금호건설 호재 4 공시

연세대학교 의료원과 3,720억 원 공사 수주, 매출 대비 18.43%. 기사 없이 공시만 있어 확산도는 빠지고, 정책 재료가 아니라 정책도 빠집니다.

규모     3   매출 대비 10~20% 구간 (객관 점수)     × 0.30
최초/독점 2   경쟁 입찰, 차별성 언급 없음            × 0.15
신규성   5   11-12 17:36 신규 공시, 최근 30일 공시 없음 × 0.25

(0.90 + 0.30 + 1.25) ÷ (0.30 + 0.15 + 0.25) = 2.45 ÷ 0.70 = 3.50 → 4점

재료 규모 기준 (공시 수치)

  • 공급계약: 매출 대비 50%↑ 5 · 20~50% 4 · 10~20% 3 · 5~10% 2 · 미만 1
  • 자사주·지분 취득·시설투자: 시가총액 대비 10%↑ 5 · 5~10% 4 · 2~5% 3 · 1~2% 2
  • 정정공시는 바뀐 부분(증액분)으로 판단

채점 원칙

  • 근거는 한 줄, 숫자와 출처 포함. 없는 사실은 쓰지 않고, 추측은 "추정"으로 표시
  • 시황 기사 속 등락 나열, 단순 시세 기사는 재료가 아님
  • 악재(유상증자·CB·소송·실적 쇼크 등)는 점수 없이 주의 종목으로
  • 재료 유형 9가지: 공급계약·수주, 실적, 자사주·주주환원, 정부 정책, 기술·특허·허가, M&A·지분, 시설투자, 협력·MOU, 기타

06리포트와 전달

리포트 구성

  • 요약과 수집 경고
  • 장 시작 전 체크리스트: 지수 흐름, 장 초반 매수세, 외국인·기관·개인 수급 (직접 기입)
  • 호재 순위표: 강도, 근거 태그 공시 뉴스 정책, 시초가·메모 칸
  • 종목별 항목 점수·근거·원문 링크
  • 공시 기반 종목, 주의 종목 악재
  • 정책뉴스 검토 결과, 수집 현황

받는 곳

  • 메일: 전체 리포트 (HTML, 휴대폰에서도 표가 깨지지 않게)
  • 텔레그램: 상위 7종목·주의 종목·수혜 정책 요약, 실패 알림
  • 파일: 미니PC reports/YYYY-MM-DD.md
  • RAS 뉴스 탭: 읽기 전용 API로 조회

07사후 검증과 가중치 조절

점수가 실제로 맞았는지 매일 기록하고, 매주 그 결과로 가중치를 조금씩 고칩니다. 기준은 D0 시가에 샀다면 종가까지 같은 시장 지수보다 얼마나 더 올랐나(지수 대비 초과수익)입니다.

기록 항목의미
시초가 갭시가 ÷ 전일 종가 − 1. 아침에 들어가기 전에 이미 얼마나 반영됐나
시가→종가, 지수 대비 초과시가 매수 기준 당일 성과에서 같은 시장 지수 움직임을 뺀 값 (가중치 조절의 목표 지표)
D+1·3·5 수익률D0 시가 매수 → N거래일 뒤 종가
D0~D+10 경로매일의 누적 초과수익과 장중 최고가. 재료 영향이 며칠 가는지 분석
비교 종목후보였지만 채점하지 않은 종목 하루 20개. 채점 종목이 정말 나았는지 비교 기준

주간 가중치 조절 규칙

  • 항목 점수와 실제 초과수익의 순위 상관을 계산
  • 표본 40건 이상, 항목별 20건 이상일 때만 조절
  • 한 번에 최대 ±5%p, 각 항목 5~40% 범위
  • 바뀐 내용은 weight_history에 기록, 채점 중에는 바꾸지 않음

재료 영향 지속성 (주간 리포트)

  • 재료 유형별, 근거별(공시·뉴스·정책) 평균 누적 경로
  • 정점: 평균 경로가 가장 높은 날과 값
  • 지속: 정점의 절반 이하로 처음 떨어진 날
  • 예: "공시 공급계약은 D+2에 +3.1%로 정점, D+5에 절반 이하"

2026-11-13 기준 표본은 아직 적어서(이틀 치) 가중치는 초기값 그대로입니다. 40건이 쌓이는 2~3주 뒤부터 조절이 시작됩니다.

08RAS 연동 API

미니PC에서 조회만 되는 API가 상시로 돌고 있습니다. 내부망 IP와 토큰이 맞는 요청만 받습니다. 명세는 docs/api.md에 있습니다.

경로내용
/api/report/latest오늘 호재 순위, 항목 점수·근거, 주의 종목, 수집 경고

/api/disclosures공시 목록, /api/disclosures/{접수번호} 본문
/api/stocks?q=종목 검색 (이름·코드 일부, 자동완성용)
/api/stock/{코드}종목의 채점 이력·주가 반응·테마·최근 뉴스와 공시
/api/dates, /api/health리포트 날짜 목록, 연결 확인

10운영 메모

문제가 생기면

  • 텔레그램 실패 알림 → 그날 아침 /morning-report 또는 morning_auto.py 재실행
  • 실패한 날을 나중에 메우려면 collect.py --since --until로 수집만 (리포트는 안 만들어짐)
  • 엉뚱한 종목이 잡히면 config/의 오탐 목록에 추가
  • 로그: data/logs/날짜.log

정기 관리

  • 연초: 다음 해 휴장일을 krx_holidays.txt에 추가
  • 실거래 키로 바꾸면 KIWOOM_MOCK=0
  • 가중치가 바뀌면 가끔 커밋·push
  • API 자동 시작 cron(@reboot, 10분 감시) 등록 확인

알려진 한계

  • 장중(07:00~15:30) 기사는 수집하지 않습니다. 네이버는 시황·전망 섹션만 모으므로 종목 개별 뉴스 전체가 있는 것은 아닙니다.
  • 뉴스·공시 데이터는 2026-11-11부터 쌓였습니다.
  • 07시 직후에는 당일 공시가 거의 없어 "오늘의공시 0건" 경고가 뜰 수 있습니다.
  • 점수는 재료의 세기입니다. 시초가에 이미 반영된 재료는 점수가 높아도 수익으로 이어지지 않을 수 있어, 체크리스트와 시초가 갭을 함께 봐야 합니다.
